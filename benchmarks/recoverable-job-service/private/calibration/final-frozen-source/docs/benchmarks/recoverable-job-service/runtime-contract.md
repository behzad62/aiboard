# Recoverable Job Service runtime contract

Version: `rjs-contract-2.0.1`. Mandatory profile: `modeled-core-v2+legacy-capsule-v1+modeled-holder-v1+authenticated-source-bootstrap-v1`.

The editable submission is **one plain ES2022 JavaScript script, `service.js`**, assigning `globalThis.createService = async function(ports, grant) { ... }`. It is evaluated as a script, not an ES module. Imports, `require`, Node, filesystem, network, dynamic host code execution and timers are unavailable in the guest. The corresponding compile-ready declarations are `contract.d.ts`. Byte arrays are JSON integer arrays, not typed arrays. These choices apply equally to public examples and final evaluation.

`createService` returns `{run(request), subscribe(jobId, listener)}`. `run` implements the discriminated request union in the declarations. All results are ordinary values. Invalid input is `blocked/input`; unsupported public format is `blocked/unsupported`; corrupt authenticated data is `blocked/integrity` (a missing/overlapping range may use `gap`). Return `stale` with the observed current owner/epoch when authority changed; transient coordinator contention is `busy`; uncertain issued work is `unknown` with the exact operation ID. Read/retry methods remain available after a failed close. Read-only inspection remains available after successful close. Starting in a closed batch is `dependency`. Recovery must never call `driver.start` again.

`poll` admits at least the currently exposed transport frame, persists evidence or allowed loss, and dispatches output observation. Consumers are fixture-registered opaque IDs: `consume` calls the asynchronous `consumer.consume` port with the actual accepted bytes. `subscribe` is observation only and does not count as consumption. During cleanup a private reader may replace an **accepted, never consumer-issued** delivery with `driver.privateRetain`, an authenticated disposition distinct from a client receipt. An ambiguous client intent cannot become private retention. On `consumer.query` = `not-applied`, an exact original delivery may be attempted; `unknown` must remain inspectable without another consumer effect.

Time advances only through deterministic controller clock events. `waitUntil({at})` requests readiness; when guest and broker are idle the driver may advance to the earliest requested tick. A wait does not extend an operation deadline. Repeated calls with the same `requestId` share the original attempt and deadline. A new request after timeout requests reconciliation, not blind reissuance. Promise settlement after timeout leaves ownership; retain the exact issued operation and reconcile using its receipt. The host observes every port rejection immediately, including falsy values. The candidate must also observe its own wrappers and preserve failure presence independently of value truthiness.

Metadata accounting is UTF-8 byte length of canonical `Evidence.spans` JSON (sort object keys recursively, preserve array order). It charges logical exported evidence, not private data structures. Adjacent loss ranges with identical stream/reason may coalesce. Protocol counters, frame identities and consumer/ACK provenance remain exact when diagnostics are lossy. Digest is SHA-256; `manifestDigest` hashes canonical JSON of the whole Evidence with `manifestDigest: ""`. `readEvidence` returns `{manifest,pieces:[{span,bytes}]}`; a loss piece has empty bytes and retains its logical range.

## Responsibility manifest

The candidate owns batching, setup intent, durable effects and recovery, selecting current authority, exact workload versus witness control, stop escalation, private intake, evidence verification/publication, consumer intent, ACK ordering, all six cleanup facts, subscriptions, capsule validation/migration, handoff, claim-holder decisions and safe reclamation. No adapter calculates a terminal verdict or enforces cleanup prerequisites. A premature process release with an otherwise valid capability is permitted by the raw port and is a candidate failure.

The provided broker owns atomic CAS documents, snapshot scans, immutable byte writes, raw process/transport observations, authenticated operation receipts, capability/fence checks, virtual clock events and fault boundaries. It does not interpret audit assertions as true. Temporary roots execute actual fixture-owned file operations; modeled process tests are not native Windows/Linux process-tree or power-loss qualification. The bounded QuickJS guest has no Node/FS/network authority. Local generated-code evaluation is the declared threat model; this is not an OS sandbox claim.

## Store and audit protocol

`store.read` returns revision 0/value null for a missing key. Keys are root-relative logical identifiers with ASCII letters, digits, dash, underscore, slash and colon, at most 180 characters. `store.scan` returns sorted matching rows in pages of 64; opaque `next` reuses the same immutable snapshot. `store.commit` atomically compares every expected revision, publishes all values (null is a tombstone), and appends all audit entries or does none. Duplicate keys reject. A CAS mismatch is `not-applied/busy`; caller may reread and retry. Mutations and audits share one durable transaction. Atomic storage survives abrupt destruction of every candidate object.

The candidate chooses its private key layout. Scenarios never inject private keys. Required audit events are declared in `Audit`. They must be committed with durable supporting state **before** the dependent observable operation: setup-intent before first owner acquisition; resource-intent before each potentially non-idempotent effect; effect-result when its receipt becomes known; checkpoint-created at its first creation; accepted before consume/ACK; consume-intent before client effect; consumed before ACK; ack-intent before publication/retirement; acked after exact retirement; cleanup-fact for each verified resource; evidence-final once; terminal-transfer and released atomically; closed only after independent inspection of every owned job; handoff atomically with the exact source/destination link. Audit is an externally observable protocol, not a storage schema or a trusted lifecycle reducer. False or missing assertions fail evaluation even if a convincing view is returned.

## Primitive payloads and error outcomes

Every port is asynchronous. Inputs and results use the declarations. Effects take `{fence:{grant,deadline}, operationId,...}`; the protected boundary checks exact token, owner, epoch, lease, deadline and raw resource identity. `applied` certifies only that effect. `not-applied` positively excludes an effect; `unknown` does not. `busy` includes earliest `retryAt`. Before-fault `not-applied`/`busy` issues no effect. An after-fault may hide an already applied effect's response; `driver.receipt(operationId)` is then either its exact Receipt or `unknown`.

Receipt fields are closed. `payload` is closed by `effect`:

| `artifact.remove` | `{absent:true}` |
| `driver.acquire` | `{resource:'isolation',allocationId}`, `{resource:'process',workload:Binding,witness:Binding}`, `{resource:'channel',channelId}`, or `{resource:'workload',workloadId}` |

Receipts are bound to exact resource/job, effect, operation, owner, epoch and appliedAt. Receipt verification authenticates bytes, not semantic consistency. An earlier epoch receipt may prove an earlier exact completed effect; future epochs and same-epoch foreign owners cannot authorize retirement. A direct driver operation does not validate candidate evidence. The candidate validates frame actual bytes, stream, seq, offset, length, digest and artifact identity, as well as contiguous counters. Publication/retirement against a changed request or frame must preserve the replacement.

Only exact immutable artifact publication, exact ACK retirement, exact CAS retry and absent-root removal are idempotent. Acquire, start, control, release, consumer and attach are not generally idempotent: query unknown outcomes rather than issuing a new attempt. A driver operation returning success is not proof that a durable owned job is released.

Each exact channel has at most one current reader attachment, shared across both `privateReader` values. Channel acquisition installs none. A newly applied `driver.attach` effect atomically installs its returned exact attachment receipt as current, superseding the prior attachment. Prior receipts remain historical evidence. A private reader uses this same slot; subscriptions/listeners are separate from it.

`driver.detach` and a new `driver.observeSource` operation require the exact current attachment receipt. A superseded receipt returns `not-applied/identity` without detaching or observing its successor. A source guard referring to the superseded attachment also refuses `identity`, even when the source revision is unchanged. Exact replay of an earlier attach operation returns its original historical receipt and does not reinstall it; reusing that operation ID with changed arguments refuses `input`. These calls retain their ordinary fencing and fault rules: an applied effect may lose its response, and a failed response alone does not prove whether replacement occurred. The raw-call example in [source-bootstrap.md](source-bootstrap.md) illustrates these outcomes.

`driver.inspect` is exclusive for the exact job/epoch. Share outstanding observation; a timed out waiter does not prove the inventory operation has finished. Observation must not block independent polling, consumption or authority work. `readChannel` is one coherent transport snapshot only; the candidate must reconcile it with its checkpoint. Retained bytes move from modeled pipes only as real ACK retirement frees capacity. Workload exit, closed pipes, empty queue, settled accepted frames and terminal barrier are different facts. `driver.barrier` may reveal final tail bytes and certifies only its two raw booleans. It never accepts bytes or settles consumer work.

`artifact.inspect` returns `absent` or exact birth/owner/alias/foreign-entry observations. Before removal the candidate proves all jobs released, all retained evidence readable, and the scratch root still exact. Retained roots never enter reclamation. An absent root is a no-effect success; an existing mismatched/aliased/foreign root is protected. On the first removal failure return exact removed/remaining IDs with `{present:true,phase:'remove',value}`, and stop additional removals.

## Cleanup and recovery

Required durable conjunction, in order: workload quiescent; output accepted and every current consumption/ACK retired through the terminal barrier; evidence finalized; channel detached; process authority released; isolation released. A private reader must attach before waiting for ACK-gated quiescence and stay until barrier plus subsequent intake finish. Setup-only jobs apply the conjunction to the subset of resources they actually acquired. Preserve unresolved acquisition intents; do not infer absence from a missing running handle. Failed start blockers carry both `jobId` and `setupId`.

Final evidence is immutable and must remain reachable after release, fresh reopen and scratch reclamation. Persist valid partial evidence if detach/release fails. The source checkpoint may retire only atomically with its authenticated terminal destination and after the current channel reader's obligation settles. Superseded attachments are historical receipts, not additional current reader obligations. This does not settle outstanding calls or change their existing reconciliation requirements. A missing checkpoint that was ever created is `missing-checkpoint`; only never-created, exact-authority setup with intact retained data can bootstrap one continuation. Reusing exact finalized evidence requires effect-free byte verification and fresh current-authority commit; changed evidence/head/epoch/deadline refuses success.

`handoff` links an exact same-batch setup to an existing successor; it does not create or launch work. Active handoff refuses foreign authority, finalized checkpoint or ambiguous client consumption. A handed-off setup is released only when its exact successor is released. Missing/foreign/unfinished destinations keep the source obligation. `recover` and close traverse all pages and account for all failures; failure remains inspectable and retryable.

## Capsule schemas and holder claims

`Capsule` format 3 is a **closed top-level** envelope; `extensions` is the only open namespace. The declaration lists every field including `checkpointEverCreated`. Validate safe integral counters, exact scope/batch/job/setup and bindings, receipt chronology, contiguous accepted frames, complete evidence coverage and manifest identity independently of its seal. `capsule.seal` authenticates the supplied envelope, including a semantically invalid one; it never grants control authority. No test assumes a private storage schema. `restore` validates before a single atomic publication or retains an explicit unknown result; stale same-epoch heads cannot overwrite a newer revision. Read evidence must recheck its head after artifact reads.

Format 1 evidence is `{format:1,kind:'evidence',scopeId,batchId,jobId,acceptedThrough:{stdout,stderr},knownPrefix:Span[],retainedSuffix:Span[],seal}`. Healthy nonoverlapping ranges are verified; uncovered prefix/interior/tail diagnostic ranges become `legacy-gap`. Do not invent consumer or ACK proof. Format 1 identity is `{format:1,kind:'identity',scopeId,batchId,jobId,numericId,terminalReceipt?,seal}`. Numeric ID never authorizes active control. Only an exact authenticated `legacy.terminal` receipt plus compatible terminal output evidence permits terminal compatibility; foreign or missing proof blocks.

The supplied `grant.holder` is the actual agent-process Binding, distinct from logical job/workload/witness ownership. `claim` must store it with logical owner and epoch using CAS. Existing exact current claim may be reused. Replacing another claim requires `driver.inspectBinding` = `dead`; alive, foreign and unknown block. The claim port provides CAS/authentication only and deliberately does not make that decision.

## Listener lifetimes and faults

A dispatch has a bounded delivery set. Only a registration still live just before invocation receives that delivery. Removal prevents later delivery in the current dispatch. A replacement gets a new ID; the old unsubscribe cannot remove it. New registrations observe fresh state later, not in the current dispatch. A single output-error dispatch must unwind even if one callback subscribes again. Callback failures cannot bypass cleanup and must remain diagnostic failures. Callbacks may synchronously initiate new asynchronous service calls.

The controller can hold/release, return busy/not-applied/unknown, or reject with any JSON/falsy/undefined value at `.before` or `.after` boundaries of every declared RPC except identity/time/hash primitives. It can advance clock, take over scope, produce output, exit workload, close pipes, consume an exact authorized release, recycle process birth, or corrupt/remove a referenced artifact. It can terminate the guest at an observed boundary and reopen the same committed store with a fresh candidate runtime. A released response may remain lost; supported exact receipt queries determine safe reconciliation. Arbitrary private-state injection is not a lawful test. Capsule semantic faults operate only through the public restore API.

A candidate fault yields a valid failed result. A broker/driver/fixture defect, missing assertion schedule, duplicate family ID, evaluator exception or violated advertised primitive guarantee yields `invalid_harness`, never a model deduction. Primary resolved is binary and requires all 69 mandatory family rows and safety assertions. A–E fractions and their equal-weight macro average are supplemental. Native OS qualification and power loss remain outside this profile.

## Release clarifications (normative, superseding broad wording above)

These rules resolve the public instruction review R1–R12. Earlier general descriptions do not widen the exact unions below.

**R1, observable responses.** All unknown IDs return `blocked/input`; contention is `blocked` with blocker `busy`. `createBatch` succeeds with `{batchId}`; `start` with `{jobId,setupId}`; `poll`, `stop`, `inspectJob`, `handoff`, and `restore` with `JobView`; `recover`, `closeBatch`, and `inspectBatch` with `BatchView`; `close` with `BatchView[]`; `consume` and `replaceRelease` with Receipt; `acknowledge` with null; `exportCapsule` with Capsule; `readEvidence` with `{manifest,pieces}`; `claim` with `{holder,logicalOwner,epoch}`; `ownScratch` with Root. `reclaim` returns `{removed:Id[],remaining:Id[],failure?:Failure}` inside `ok`; `failure.present` means partial reclamation failed and is **not** successful reclamation. An outer blocked response is used when the pre-disposal proof fails before removal. `JobView.failures` contains retained service failures, and unresolved effect records appear in `obligations` with exact attempt IDs. A failed start after its setup-intent exposes jobId/setupId on every relevant blocker and inspection; failure before creating a record has no invented IDs.

**R2, lawful faults.** The nonfaultable methods are `now`, `newId`, `digest`, `verify`, `authority`, `waitUntil`, `capsule.seal`, `capsule.verify`, and `driver.receipt`. Other raw-return methods (`store.read`, `store.scan`, `artifact.read`, `artifact.inspect`, `driver.inspect`, `driver.inspectBinding`, `claims.read`, `consumer.query`, `consumer.consume`) may be held or reject, never return Primitive tags. Primitive-returning methods may be held or reject before/after, return busy or not-applied **before only**, and return unknown **after only**. An exception's truthiness is irrelevant. A rejection is ambiguous unless an exact receipt query or CAS readback proves application/nonapplication; do not infer safety from the before/after location, which the guest does not receive. `consumer.query` is the only reconciliation source for client delivery. Receipt queries for other operations cover store, artifacts, claims and driver effects throughout the case and across guest restarts.

**R3, mutation identity.** `store.commit` and `claims.cas` require caller-generated `operationId`. Store/claim receipts use resourceId = grant.scopeId; artifact receipts use root.id; driver/consumer receipts use jobId. Exact store/claim CAS readback with a candidate-persisted attempt marker is also a permitted reconciliation strategy. No resource-intent is required for a store transaction itself (that would recurse forever): its caller-known operationId and atomic CAS marker provide attribution. Repeating an exact successful CAS operationId returns its original receipt, without replaying writes or audits; changed writes/assertions with that ID reject `input`.

**R4, audit schema and facts.** Each event carries the following required fields. Optional prose/extensions may be ignored. `setup-intent`: jobId,batchId,data.setupId. `resource-intent`: jobId,operationId,data.resource (the candidate's resource/effect label). `effect-result`: jobId,operationId,receipt if the effect result is a Receipt. `checkpoint-created`: jobId,data.generation. `accepted`: jobId,frame,data.evidenceRevision and optional data.loss. `consume-intent`: jobId,frame,operationId=deliveryId. `consumed`: jobId,frame,receipt. `ack-intent`: jobId,frame,receipt=consumption. `acked`: jobId,frame,receipt=retirement. `cleanup-fact`: jobId,fact,data.receipts. `evidence-final` and `terminal-transfer`: jobId,manifest. `released`: jobId. `closed`: batchId. `handoff`: jobId,data.setupId or data.successorJobId. Audit is atomically stored alongside the candidate's supporting state; the hidden oracle verifies it against actual observed raw facts, payload artifacts and effect receipts, never merely against the assertion text.

`facts.quiescent` contains control/release receipts when these were needed and may be empty after an observed already-exited/not-started workload. Its proof is the actual exact-binding inventory observed before the current-authority commit. `facts.output` contains the positive terminal barrier Receipt (empty only when no channel was acquired); its proof also requires empty transport/buffer and exact sourcePrefix+consumed=sourcePrefix+acked=accepted=produced totals. `facts.evidence` may be empty: its proof is the byte-verified immutable exported manifest and matching evidence-final commit. Channel/process/isolation fact arrays contain their exact detach/release receipts, or are empty only for an owner never acquired. The evaluator accepts different private proof layouts and checks raw observations plus committed public facts. Facts must preserve their original receipt attribution on takeover.

**R5, canonical evidence/capsules.** Ranges are `[start,end)` byte positions. Spans are ordered within each stream, interleaving streams freely, and cover exactly `[0,totals[stream].accepted)` without overlap/gap. Byte spans require digest, artifactId, root, name and forbid reason; loss spans require an allowed reason and forbid digest/artifactId/root/name. In this wire format each byte span is one exact retained transport frame: artifactId equals the FrameKey artifactId, name is a logical immutable artifact name (no filename convention is assumed), root.owner is jobId, root.retained is true, and read bytes hash/length match. Internal coalescing is allowed if export reconstructs these spans. Totals satisfy `0 <= acked <= consumed` and `sourcePrefix + consumed <= accepted <= produced`. At finality `accepted = sourcePrefix + consumed = sourcePrefix + acked = produced`. Ordinary zero-origin jobs have sourcePrefix=0 and sourceProof=null. Evidence version is exactly 3, revision is a nonnegative safe integer, and generation is an ID. Capsule revision equals evidence.revision; checkpoint.generation equals evidence.generation; checkpoint.authority equals capsule ownerId/epoch. createdAt is nonnegative and not in the future. Consumed/retired receipt appliedAt is >=0 and <= current now, never a future epoch; same-epoch foreign owner rejects. Earlier exact receipts retain earlier attribution and may precede current checkpoint reattachment. Capsule top level and FrameKey are closed. Other nested objects accept harmless extra fields but never use them for authority. A changed immutable finalManifest/evidence pair rejects; when finalManifest exists it equals evidence exactly.

**R6, joint capacity and compact history.** A legal scenario has at most **128 frames per job and 512 frames per case**, in addition to every byte/job/batch bound above. These are joint upper bounds; the 8-MiB guard does not authorize exceeding the frame count. Many tiny-frame metadata tests use 128 one-byte frames; 262,144-byte payload tests use 64 full chunks. Wire and document limits measure UTF-8 serialized JSON bytes. A capsule is an export, not a required single private document. `checkpoint.accepted` and `checkpoint.consumed` contain only **not-yet-retired** frames/receipts. `checkpoint.retiredThrough` supplies per-stream `{seq,offset,receipt}`: seq is the next sequence after a contiguous retired prefix, offset its ending byte position, receipt the exact last suffix retirement receipt (null for zero/zero or the exact authenticated source baseline described in source-bootstrap.md). `retirement` contains at most those two last receipts. Validate that each suffix retirement is certified by its final exact ACK receipt and agrees with cumulative evidence; source-only baselines require the exact sourceProof instead; outstanding accepted frames continue from that seq/offset. Historical per-frame delivery records may remain in separately paged candidate storage; they are protocol state and are not counted as diagnostic span metadata. An imported capsule does not erase earlier durable protocol records. Exact historic replay may use authenticated receipt+certified retired prefix without another consumer/ACK effect. The compact representation fits the public export bound at legal maximum frame counts.

**R7, retention policy.** A before-write `not-applied` code `privacy` is the exact privacy denial; `backend` is diagnostic I/O refusal. Only those outcomes allow `privacy`/`diagnostic-io` loss. Unknown publication must be reconciled and is not loss permission. While both diagnostic budgets can admit a frame, retain its healthy bytes; no discretionary always-loss policy is valid. A next full frame that would exceed payload capacity may become payload-budget loss; after canonical spans would exceed metadata capacity, next frames may become metadata-budget loss. Preserve all earlier retained spans. Reserve up to 2,768 metadata bytes for exact coalesced loss accounting, so beginning metadata loss once prior spans exceed 30,000 bytes is legal. Never relabel integrity, authority, CAS or checkpoint failure as diagnostic loss.

**R8, modeled lifecycle.** Acquire order is isolation, process, channel, workload; persist each intent before acquisition and identity before start. The process receipt creates distinct workload/witness bindings. Channel acquisition creates transport, not a reader; attach installs one. Start transitions not-started→running and has no terminal guarantee. Graceful requests workload exit, which may remain running; force requests termination and requires a fresh exact workload binding. Inspect after control is required. At most one graceful and one force effect per joined stop attempt; force is legal only if still running after 100 ms grace, before deadline, with valid authority. Unknown inventory never permits force. `exit` describes the **workload**. Quiescence is exact-binding not-started or exited; exited code may be nonzero after explicit stop. A claimed natural release (`exit.natural=true`) additionally requires code zero and an authenticated consumedRelease bound to the exact published request, owner, epoch and witness. Publication or witness absence alone is insufficient. A release request coordinates the witness; it does not itself prove workload exit, pipe closure or consumption. Process release retires witness authority; isolation release drops allocation. A barrier can be blocked (both booleans remain false), can expose final tail, and on already-exited/not-started workload may close pipes; only its actual positive facts count. Setup cleanup applies exactly to acquired owners; an unissued acquisition intent does not authorize acquiring it merely to close it.

**R9, retries/closing.** Request IDs are service-scope identifiers bound to type, target and original deadline. Changed arguments under a reused ID reject input. Same-ID completed calls replay their durable result after restart. Concurrent stop/close observers of one job join the exact outstanding stop attempt even with different IDs; the earliest issued attempt's original deadline governs all joining waiters. After a timed out operation, a new ID may reconcile its exact retained effect but cannot replay an unknown effect. `recover` actively settles every unfinished owned record toward release; it never relaunches. closeBatch changes open→closing before cleanup; start rejects closing/closed batches. New batches remain allowed until successful service close, which durably prevents createBatch/start thereafter. Failed service close keeps inspection/recovery/close retry usable. Equality `expiresAt == deadline+100` is sufficient. Input validity is checked before work; for simultaneous invalid authority/deadline/lease, authority or deadline refusal are both safe, but no effect/success is allowed.

**R10, handoff and legacy composition.** A setup source in setup/running/blocked/stopping with nonfinal evidence and no consuming-unknown frame may link an existing same-batch running or released successor. Self-links, cycles, foreign owner/epoch and another already-linked destination reject dependency; exact retries reuse the link. Stop on the source blocks until the exact successor is released. A finalized/released source cannot initiate active handoff; terminal evidence transfer is performed by the source's own atomic released transition. Legacy restores target an **already existing exact job**; they do not generate jobs/setup IDs or bindings. LegacyEvidence only replaces diagnostic evidence with verified ranges/gaps, leaving client/ACK facts unclaimed. LegacyIdentity is an effect-free compatibility check on an already released job with complete valid final output/evidence and exact terminal receipt; before complementary proof exists it blocks without publication. Either public restore may be retried; it never grants numeric-ID active authority.

**R11, event triggers.** Output fires only after a newly accepted frame commit caused by poll/private intake; it is observation, not delivery. Error fires once for a failed intake dispatch, with categorical blockers, and does not claim terminal. Terminal means fully durably released, not workload exit. Subscribe queues a fresh asynchronous terminal observation if the job is already released; ordinary fresh output requires poll. Subscription unsubscribe is the cancellation/detachment surface for observer delivery and synchronously suppresses that registration, including later callbacks in the current snapshot. There is no independent cancel RPC: cancellation cases detach an observer while its previously issued exclusive inspection remains owned until settlement. Replacement subscription is a new registration lifetime. New registration in an error callback must not recursively receive that same error dispatch.

**R12, public scratch ownership.** A candidate need not create gratuitous scratch roots. `ownScratch({jobId,root})` is a public request for the service to adopt a fixture-supplied authenticated scratch root. Inspect and validate exact owner=jobId, birth, no alias/foreign entry, retained=false, and persist its obligation before success. It creates no workload. Such roots must be rediscoverable after reopen and are included in reclaim alongside any optional candidate scratch roots. Tests exercise deletion with at least three such adopted handles, so the second-failure case is representation-independent. Reclaim order may vary, but must stop at the first error and report actual removed/remaining roots exactly. A root absent before adoption rejects owned-path; absence after durable adoption is a no-effect reclaim success. Immutable write retry requires same exact root identity, name and bytes; changed bytes reject integrity.


### Four follow-up clarifications

Scope-only claim acquisition is exempt from job resource-intent/effect-result audit rows: claims.cas carries the preknown operationId, scopeId receipt, holder/owner/epoch and exact CAS version. This does not authorize omitting job effect audits.

Capsule revision/generation/authority equalities involving evidence/checkpoint apply only when those objects are present. A never-created setup may export checkpointEverCreated=false, checkpoint=null, evidence=null, revision=0; accepted/consumed/retired totals are then absent, not invented zero history. checkpointEverCreated=true with checkpoint=null is always missing-checkpoint. A present checkpoint requires matching present evidence.

Receipt and its effect-discriminated payload remain closed exceptions to the general rule allowing harmless nested extensions. Capsule top level, FrameKey, Receipt and its payload are closed; other nested data may carry ignored extensions. The raw consumed natural-release receipt is effect driver.releaseConsumed, resourceId=jobId, payload={requestId,ownerId,epoch,witness}; it records actual consumption of the exact current release request.

This runtime contract and contract.d.ts define the executable modeled profile and supersede provisional interface wording in problem.md and acceptance-contract.md. In particular active handoff accepts the source/destination states in R10, error notification means intake error rather than terminal release, and cancellation/detachment are the public subscription actions in R11. Companion family narratives do not add an undisclosed RPC or stronger proof layout.


### Scoring schedules and public recipes (suite rjs-suite-2.0.1)

Production scoring executes all mandatory variants of all 69 families. Each family passes only if every variant passes and its observed causal trace was checked. Per-variant diagnostics record executed assertions, physical-operation and promise-job counts, and whether safety was measured. After a watchdog expires, remaining variants are failed/unexecuted/unmeasured; empty safety failures alone never mean checked-safe. Cancellation is an AbortError and remains distinct from a scored timeout.
