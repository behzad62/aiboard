# Independent review of the native draft (not final acceptance)
Observed during implementation-1. No controller product edits while the worker owns implementation. Recheck these against its final source before treating them as outstanding.

1. `SubprocessRuntime.recoverExceptional` accepts an optional assertGrant callback and a mutable request object. Original `invoke` snapshots its input; recovery reads request.action again after awaits. Add a direct-kernel regression changing inspect to terminate while backend reattestation/reconciliation is blocked; it must never signal. The last-mile grant must be mandatory and backed by the original opaque grant authority in the real host, not an optional or model-supplied no-op callback.
2. The draft checks assertGrant only before lease takeover and before each signal. It also needs current-authority/deadline checks immediately before native probe/reconcile/verify effects and before any subsequent destructive phase after an await. Test revoke/cancel during reattestation, reconciliation and first signal; no later signal/force escalation may run.
3. After a signal reports identity_mismatch/outcome_unknown, the draft continues reconciliation and may force-terminate later. Stop the exceptional sequence immediately on either ambiguous result; never try another action hoping ambiguity clears. Test a backend that reports mismatch on signal then running on reconcile.
4. Final selected attestation must independently enforce action-required capabilities; do not rely only on pre-proposal cached capability flags.
5. Empty verification is not resource release. The draft sets cleanup verified_empty but never releases backend/output ownership; lifecycle stays in an exceptional state ordinary reconcileStartup skips. A real-host termination test must assert no retained native process/backend/lease/output resources, or keep those resources explicitly blocked and do not claim complete cleanup. Do not invent exit/output facts to force normal finish; add an exact, proven closure path.
6. The false-empty branch tries to consume backend_verify_empty with record_exceptional_observation, but the new EFFECT_CONSUMERS table does not allow that pairing. It will throw rather than persist the intended observation. Cover the actual kernel false-empty path, not only the controller fake result.
7. Exact reattestation-only forbids every fresh registry instance after restart. Existing adoptProcessBackendAfterRestart verifies the same implementation digest; its role is not to change implementations. Reuse its proven adoption semantics under exact ownership where supported, or explicitly classify the boundary unavailable rather than claim recovered restart execution. Test real kernel reconstruction on the same durable state.
8. `identityProof` in record_exceptional_* currently checks only hexadecimal syntax, not equality to the record binding; it is a claimed fingerprint, not independent proof. Keep backend/native proof in the kernel, and validate durable binding association/semantic effect family so a wrong identity digest is not accepted as that record's evidence.
9. The draft subprocess-runtime.ts contains two literal NUL bytes in fingerprint join strings, making Git classify it as binary. Use an unambiguous canonical serialization (or escaped source spelling with validated components). Product source must remain reviewable text.

Required final test review: bounded timeout/in-flight unknown semantics, full-scope/PID-only reversal, no silent signal retry, exact original grants, complete resource accounting, and actual host/API/client wiring. The above are hypotheses/code findings against an interim draft; preserve their validation results rather than blindly patching unverified assumptions.
