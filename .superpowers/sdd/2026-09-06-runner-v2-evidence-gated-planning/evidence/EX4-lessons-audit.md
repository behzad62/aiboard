## Precondition that qualifies every verdict

**P0 — the new-policy flow is not reachable in production today.** Every T6a/T6b mechanism (deliverable review,
boundary checks, acceptance, repair budgets, approach decisions, flaky isolation, OA-17 cleanup search, defect classes)
is gated on `planningPolicyVersion === 1` (for example `build-runtime.ts:967,1029,2161`). Nothing in `src/` emits
`planning.policy_configured`; only tests seed it (T6a evidence, "Not done / limits": "reachable only from seeded runs until T7").
So a run built by `native-build-factory` and driven by `BuildRuntime.step` today takes the legacy path.
The verdicts below describe the new-policy path, which is what P6.6 delivers once T7 stamps the policy.
**Ask for T7's DoD:** one unseeded factory test that starts a run the production way and reaches
`delivery.review_started` → boundary → `task.acceptance_recorded`.

**Second cross-cutting finding (L3 inside the runner itself).** T5's mechanical APIs are library-only. Nothing in
`src/` outside their own files calls them: `validation-observation.ts` (`createValidationObservation`,
`assessObservationForAcceptance`:205, `recordRedGreenPair`:337, `recordFaultInjection`:395, `recordFlakyIsolation`:452),
`evidence-applicability.ts` (`decideApplicability`:89, `decideUnverifiedClaim`:236) and `createValidationEvidenceTools`
(`evidence-tools.ts:51`, not granted to any role). T5 passed 12 review rounds with these unwired. This is exactly L3.
T8's synthetic qualification ("unrelated-change reuse, related-change invalidation") will fail on it unless it is wired first.

Severity scale: **HIGH** means no deterministic runner gate exists, and a worker could get bad work accepted or
corrupt/leak user files. **MEDIUM** means a reviewer or boundary backstop exists, or the effect is waste, stalls or
misleading records. **LOW** means cosmetic or already visible to the owner.

## Recommended packets before T8 (ordered by severity; all four are HIGH)

1. **Test-integrity boundary guard (N1, L4a).** In `delivery-execution.ts` / the boundary record, pin the tests
   command to the last accepted integration revision's profile when the candidate changed the test script or test
   config. Store the executed count per accepted boundary, and fail a later boundary with "suite shrank N→M" or
   "test command changed" unless the Architect records a reason tied to a plan revision.
   Test: factory fixtures where the worker narrows the script or deletes a test case turn the boundary red; an unchanged
   control stays green.
2. **Submission scope and secret guard (L17, N2, N4-part).** New pure module called at submission
   (`change-set.ts` `createChangeSet`) with the task's assignment claim.
   (a) Refuse paths matching `forbiddenSurfaces` or a default forbidden set (`AGENTS.md`, `CLAUDE.md`, `.github/`, `.git*`)
   unless claimed. Record other out-of-claim paths as a blocking mechanical finding that needs a plan revision.
   (b) Refuse added lines that match secret patterns (private-key headers, `AKIA…`, `sk-`/`ghp_`/`xox` tokens,
   sensitive-key assignments with long literals) and new `.env`/`*.pem`/`id_rsa` files, with the reason redacted.
   Test: one fixture per class plus a clean control.
3. **Review independence and depth floor (N5, N3, L3).** (a) Record every runtime assigned to the task attempt as a
   change author at `delivery.review_started`, so a failover co-author is excluded from `distinct_model`.
   (b) Add a runner-signals section: new non-test source files that no non-test file references, and test-only or
   test-config diffs. Either raises the tier to at least medium.
   (c) Require ≥1 inspection call at low tier as well.
   Test: the failover scenario excludes A; an unreferenced module is flagged; a test-only diff is at least medium;
   low-tier findings without inspection are refused.
4. **Encoding safety (L6).** Keep an existing BOM in `fs.patch`/`fs.write` (`filesystem-tools.ts:818`). Add a
   submission check for BOM added or removed, a line-ending flip or newly mixed endings, U+FFFD or mojibake in added
   lines, and invalid UTF-8. Test: patching a BOM+CRLF file round-trips byte-exact; each detector trips on its fixture.
