## Design choices

- Docs-gate rule for answered runs: a pure answer NEEDS the STATE.md gate. The
  capability program's rule for runs that change nothing is AC-25: even `plan_only`
  runs, whose whole product changes nothing in the project, cannot complete until
  `docs/project/STATE.md` is committed. Answered readiness therefore runs beside
  `projectDocumentationReadiness` (G-3), never bypassing it; with zero integration
  the recency check is vacuous, so STATE.md committed at any point in the run
  satisfies it. `write_project_doc` stays on the answer path for exactly this.
- Conversion semantics: `request.converted_to_build` is the only way back from
  `answer` (re-triage is refused); it flips the decision to `build`, so the run is
  in planning state again and planning proceeds normally. There is no path from
  `build` back to `answer` (tasks may already exist — fail closed).
- Clarify resume: `clarify` is recorded durably, then `ask_user` blocks; on resume
  the run re-triages. `plan_required` matching now accepts architect-authored
  triage events and planning progress events (the T3a seam); legacy runs emit none
  of the added types, so legacy matching is unchanged.
- Triage-first vs `plan_required`: the Architect reason union lives in
  `user-steering-contracts.ts` (not writable) and checkpoints strictly validate
  it, so no new reason type was possible. Triage therefore rides the Architect's
  normal first `plan_required` turn per the brief ("not an extra model call"), and
  "triage precedes plan_required" is enforced as no *planning* before the triage
  decision: planning tools refuse and the kernel refuses planning progress until
  triage is `build`; the first turn offers `record_triage`.
- Answer review: one review per run from the pump (`answer_review_1`); the verdict
  is advisory evidence (any recorded verdict satisfies completion when opted in);
  a re-review with a prior review is supported at the runtime level with the full
  OA-10 #2 device (own findings → release → verdict with per-finding checks).
- Completion keeps the existing handoff ceremony (explicit user choice); answered
  runs select handoff with a `no_integration` revision marker, match-exempt like
  plan_only.
