## Fix delta, both directions

- **Forging.** `findSnapshotCommit` requires the runner author and committer identity and all four trailers in the trailer block within `baseline..HEAD`. A `-x` cherry-pick line ends the block. The runtime also requires a digest-valid STATE.md and the v2 entry facts before it records. I found no forging path.
- **Double recording.** Reconciliation skips stops already present in `snapshots`. The reducer refuses a second record for the same `stopSequence`. The idempotency key is per stop. The probe-F path and reconciliation cannot both record the same stop. Not found.
- **Tip movement.** History is walked in chronological order, and the tip moves only when parent == canonical or tip. G2-test is correct. The wrong-tip outcome is G3 (B2). Separately, the reducer accepts a record for a sequence that is **no stop** while a handoff is requested and moves the tip to it (probe R: tip → `bbbbbbbb`). The runtime never produces such a record, and the gate still refuses it (N-3).
- **Current stop treated as history?** No. `isCurrentStop = requested && stopSequence === requestedSequence` (`scheduler-store.ts:9315`). The current record still clears the failure pause and flips running to paused (G2-test, H).
- **Gate satisfied by a history record?** Not while a request exists: `handoffSnapshotAtCurrentStop` filters by `requestedSequence`. The `latestRequest === undefined` fallback takes any record, history included. No live producer reaches it, because `complete_run` emits `project.handoff_requested`, not `run.completed` (N-7).
- **Byte splice.** Bytes outside the markers are exact. EOL matches for the single-line v2 bodies. The v1 Architect path is identical on LF files. On CRLF files it now puts CRLF around the markers, but the multi-line v1 body keeps LF (N-5; the v1 check still passes). The link skip changed the v1 path (N-4).
- **Spec-copy failures never fail the snapshot?** True for failures while deciding the copy. False for failures while writing or staging it (N-1).
