`read-only-class` admits a definition only when `readOnly === true` and `effect === "external"` and `isMcpToolName(name)`. A missing name is refused.

Plan-only comparison. A1's `read-only-non-workspace` predicate is `readOnly && effect !== "workspace"`. On mapper output it admits the same MCP tools as the class: `createMcpTools` always sets `effect: "external"` and always names tools `mcp.*`, so both predicates reduce to `readOnly === true`. The old predicate is weaker off that output: it admits an MCP-named read-only definition whose effect is `none` (`role-capabilities.test.ts:368` expects `true`; the class at `:371` expects `false`). Because it can admit more than the class, architect planOnly now selects `read-only-class`. The old predicate stays implemented and is not selected by any surface. Plan-only's separate non-MCP extension filter (`readOnly && effect !== "workspace"` for a non-catalog name) is unchanged.
