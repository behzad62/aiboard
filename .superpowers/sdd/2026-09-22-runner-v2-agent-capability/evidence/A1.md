### A1b.1.1 Derived list (by construction)

`architectLifecycleUniverseNames` calls `createArchitectTools` for every shape `runArchitect` can register (finish, budgeted, plan-only, plan-only completion, context-recording decision, user guidance, the four verification/repair flags, and plan-critique resolution). Sorted union (16):

`acknowledge_user_guidance`, `answer_guidance`, `ask_user`, `complete_run`, `plan_final_verification`, `plan_tasks`, `plan_verification_repairs`, `plan_verifier_repairs`, `reconcile_plan`, `request_integration`, `resolve_context_recording`, `resolve_plan_critique`, `review_final_verification`, `review_task`, `revise_task`, `upgrade_acceptance_contract`.

`resolve_context_recording` is in the union. So is every name in `ARCHITECT_LIFECYCLE_TOOLS`.

One Architect turn registers a subset. `createArchitectTools` adds reason-gated tools, and `plan_only` omits `review_task`, `request_integration`, and sometimes `complete_run`. The existing plan-only test locks those reduced sets. Exact equality at registration is therefore the constructed union against `ARCHITECT_LIFECYCLE_SURFACE`: any name the union gained, or any name the constant still lists that the union no longer produces, throws before tools are registered. Each registered name must also be in the constant. When `runPolicy` is not `plan_only`, every `ARCHITECT_LIFECYCLE_TOOLS` name must be present. That presence check is separate from catalog equality so dropping it reddens the `review_task` test without the catalog check also throwing.

The test supplies `architectLifecycleProbe`. Production callers leave it unset. It is not a flag that drops a named tool.
