### 1.1 Event and projection

`project_doc.requested` payload: `requestId`, `path`, `contentArtifactHash`, `contentBytes`, `summary`. Actor role `architect`. `requestId` is `project-doc:${logSequence}:${normalizedPath}` and is also the idempotency key. `logSequence` is `projection.lastSequence + 1`, read from the scheduler projection immediately before `append`. That is the position `SqliteSchedulerStore.append` assigns with `COALESCE(MAX(sequence), 0) + 1` inside `BEGIN IMMEDIATE`. The Architect action sequence is not part of the id, so two writes of one path in one turn get different ids. The reducer still rejects a `requestId` already stored on `projectDocs.pending`. The reducer stores `checked.path` on `projectDocs.pending` with the event sequence. A5 adds `project_doc.committed`. The event is not an architect lifecycle decision, so it does not set `lastArchitectActionEvent`. The tool returns `Project document requested: <requestId>` and does not emit an `architect_action` signal, so the turn can continue.
