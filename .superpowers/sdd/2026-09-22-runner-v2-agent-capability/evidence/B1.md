### Idempotency, why retry is safe

`store.record` for the same manifest id is idempotent. `SqliteContextManifestStore.record` (`runner-v2/src/sqlite-context-manifest-store.ts:47-62`) uses `INSERT OR IGNORE` on `manifest_id` (the primary key) and then returns `get(manifest.manifestId)`, the row already stored. The existing test at `runner-v2/test/context-manifest-store.test.ts:127-129` records the same identity twice and asserts `again.manifestId === first.manifestId` and `again.recordedAt === first.recordedAt` ("a duplicate identity keeps the first record").

`artifacts.put` is content-addressed. `digest` is SHA-256 of the bytes (`runner-v2/src/artifact-store.ts:40-41`). `put` addresses the payload by that hash (`artifact-store.ts:81-84`, paths at `artifact-store.ts:172-183`). `writeAtomicIfMissing` returns immediately when the destination already exists (`artifact-store.ts:53-54`). A repeated put of the same pack text names the same hash and does not rewrite an existing payload.
