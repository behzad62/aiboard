# Runner V2 filesystem owner review — 2026-11-18, CW6 (evidence re-runs of a CLI worker's checks)

Scope: packet CW6 of `docs/plans/2026-11-14-cli-workers.md` (§3.6). No module newly imports a mutation-capable `node:fs` API: the new module `runner-v2/src/cli-worker-evidence.ts` imports none. Two reviewed owners gain writes with the APIs they already import, recorded here. Source references are relative to `runner-v2/src/`. This is a static review of the change, not a sandbox. The regression coverage is in `runner-v2/test/cli-worker-evidence.test.ts` and the CW6 test of `runner-v2/test/git-run-context.test.ts`. The entries in `runner-v2/test/filesystem-mutation-routing.test.ts` refer to this record.

| cli-worker-runtime.ts (CW6 addition) | `mkdir`, `writeFile`, `readFile` (unchanged set) | the CLI worker session's folder `cliWorkerStateFolder(stateDirectory, runId, sessionId)`, reviewed for CW5 | `run-<n>.fix.json`: `{ version: 1, prompt }`, the fix round's prompt for run `<n>`, where `<n>` is the count of the attempt's durable records plus one, written when a run's re-runs left a gap and the attempt still has its fix round. ## Notes
- The re-runs themselves are `run_evidence_command` calls through a ToolBroker, as an API worker's are: the command's writes are the project command's own, under the worker's grant, exactly as when an API worker runs the same check. CW6 adds only the restore afterwards.
- The restore runs only when the trees before and after the re-runs differ. When the tree cannot be captured before or after, the attempt fails with `cli_checks_rerun_failed` and nothing is submitted.
