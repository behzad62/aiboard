## Adopted contract

- Lifecycle proof has one explicit scope: `process_group` or `contained_workload`.
- Termination and emptiness are claims inside that recorded scope. `crash_cleanup` and `write_confinement` remain independent.
- Ordinary `full` execution asks for `process_group`. Non-full isolation, an explicit complete-cleanup requirement, or known unavoidable detachment asks for `contained_workload`.
- A contained workload may satisfy a process-group request; a process-group provider never satisfies a contained-workload request.
- POSIX native ownership remains authenticated process-group ownership. PPID ancestry is not ownership authority and is never used to manufacture descendant cleanup.
- Windows Job and configured OCI are the existing contained-workload providers. The sampled non-Job Windows fallback is not Job-equivalent; when it cannot meet the requested lifecycle it is unavailable before launch.
- OCI workload containment and the host attach/control process lifecycle are separate boundaries; killing the host attach process does not discharge the container lease.
- Old records remain available for exact owned cleanup but missing scope is never upgraded to containment and never authorizes replay.
- Node release evidence remains Node 24 only, consistent with the previously adopted project policy.
