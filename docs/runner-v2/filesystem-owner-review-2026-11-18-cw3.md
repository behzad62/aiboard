# Runner V2 filesystem owner review — 2026-11-18, CW3 (CLI worker detection and the Test button)

Scope: the new module `runner-v2/src/cli-worker-detection.ts` (packet CW3 of `docs/plans/2026-11-14-cli-workers.md`, §3.2 and §3.4). Source references are relative to `runner-v2/src/`. This is a static review of the change, not a sandbox. The regression coverage is in `runner-v2/test/control-server-cli-workers.test.ts`. The entry in `runner-v2/test/filesystem-mutation-routing.test.ts` refers to this record.

Why it writes: the free checks and the Test must run from folders the Runner owns, never a worktree or a project folder. On Windows VF2's lookup searches its own folder before PATH, so a `claude.cmd` or `codex.exe` committed at a repository's root would otherwise shadow the real CLI (CW2's lookup note). The Test runs a CLI in an empty folder (§3.4), and Codex and agy read the result schema from a file.

| cli-worker-detection.ts | mkdir, rm, writeFile (`node:fs/promises`); readFile is a read | 3: fixed Runner-private folders under the state directory | (a) `<state>/cli-workers/lookup`, created with `mkdir` (recursive, 0700) before each free check; nothing is ever written into it. `cli-worker-adapters.ts` (CW2) imports only `stat`, a read, and needs no routing entry. The control-server routes and the Build manager's `providerTestPassed` write no file: the Test result goes to the home through `applyHomeBatch` (aiboard-home-store.ts, reviewed 2026-11-12), and the cooldown's end is a scheduler event (sqlite-scheduler-store.ts).
