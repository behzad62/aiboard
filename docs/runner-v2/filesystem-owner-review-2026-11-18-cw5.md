# Runner V2 filesystem owner review — 2026-11-18, CW5 (the CLI worker loop's state folder)

Scope: the new owner `runner-v2/src/cli-worker-runtime.ts` (packet CW5 of `docs/plans/2026-11-14-cli-workers.md`, §3.5 step 2), and the CW5 additions to the reviewed owner `runner-v2/src/workspace-manager.ts`. Source references are relative to `runner-v2/src/`. This is a static review of the change, not a sandbox. The regression coverage is in `runner-v2/test/cli-worker-runtime-outcomes.test.ts`, `-stops.test.ts` and `-runs.test.ts` and the CW5 tests of `runner-v2/test/workspace-manager.test.ts`. | cli-worker-runtime.ts | `mkdir`, `rm`, `writeFile` (`node:fs/promises`); `readFile` reads only | 3: fixed Runner-private files | One folder per worker session, `cliWorkerStateFolder(stateDirectory, runId, sessionId)` = `<state>/cli-workers/<runnerRunStateSegment(runId)>/<runnerRunStateSegment(sessionId)>/`. Both segments are the Runner's own bounded, hashed segment function (the one the Playwright CLI folders use), from Runner ids, never model-selected. Inside it only fixed names: `result.schema.json` (the CLI result schema, for Codex and agy), `last-message.json` (Codex's `-o` file), `run-<n>.launch.json` and `run-<n>.result.json`, where `<n>` is the count of the attempt's durable records plus one. | `mkdir -p` of the folder; `rm --force` of `last-message.json` before every launch, so an earlier run's Codex result is never read as this one's; `writeFile` of the schema; `writeFile(..., { flag: "wx" })` of the run's launch record (the branch tip and project state before the CLI starts; a later run with the same number reuses it, which is how a run the Runner stopped during keeps its tip), and only then `rm --force` of that run's `run-<n>.result.json`, which no attempt record digested; `writeFile(..., { flag: "wx" })` of the run's result record, which never replaces an existing file, and whose sha256 is recorded in the `worker.cli_attempt_recorded` event a collect-on-resume checks. The folder is outside the worktree and the project, so a CLI at Full access in its worktree does not write there by its working directory; Codex's `-o` path is the only path in it a CLI is told about. | (a) The CLI runs as the user and can write any file the user can, this folder included. That is why the result file is digested in the durable record and refused on mismatch, and why a pending collect also compares the worktree's HEAD and tree hash with what was recorded. (b) Nothing removes the folder when the run ends: it is per-run state under `<state>`, like the Playwright CLI owner folders; a run-folder cleanup is a follow-up. It holds the CLI's result JSON, its reading (usage, session id, the summary or failure text) and the Runner's own facts. The failure text is kept as the CLI's reader produced it, not redacted (only the scheduler record's summary is), so a CLI that printed a secret in its error leaves it in this per-user state folder, as the CLI's own logs do. |
| workspace-manager.ts (CW5 additions) | unchanged set; the new methods run only `git` through the manager's runner | already reviewed: Git-worktree lifecycle | `undoForeignCommits` moves the task branch with a compare-and-set `git update-ref <branch> <recordedTip> <head>`; `restoreProjectDocs` runs, all on the literal pathspec `:(literal)docs/project` only and all within the Runner Git policy (git-execution-policy.ts, git-run-context.ts `MECHANICAL`), `git reset -q <baseline>` (the index), `git checkout <baseline>` when the baseline has `docs/project` (the worktree), then `git clean -f -d`; `projectFolderState` only reads (64 MiB capture, and its `status` runs with `GIT_OPTIONAL_LOCKS=0`, the one value the Runner Git policy accepts for that variable, so it never refreshes the user's index); `assertOnTaskBranch` only reads. The Runner's own last commit on a worktree (`runnerTip`, with the baseline it was made on) is a new field of the existing workspace-owner record `workspace-owners/<run>.json`, written by the same `saveWorkspaceOwners` after each guarded commit and cleared when the worktree starts on a new branch; no new file. | Each method checks the workspace's run and its owner (`assertWorkspaceTaskOwner` / `assertOwnedWorkspace`) and runs inside the manager's serialization, like `commitWorkspace`. `undoForeignCommits` refuses, changing nothing, an unsettled merge, rebase, cherry-pick or revert, a detached HEAD, another branch, a recorded tip that is not an ancestor of HEAD, and a merge commit after that tip. `restoreProjectDocs` verifies afterwards that the worktree, the index and the untracked files under `docs/project` match the baseline, and throws otherwise. | The `git clean` is confined to the task worktree's `docs/project` by its literal pathspec; ignored files are left, as the verification also ignores them. |
