# Runner V2 filesystem owner review — 2026-11-12, HM1 (the AIBoard home store)

Scope: the new native filesystem owner `runner-v2/src/aiboard-home-store.ts`, added by packet HM1 of `docs/plans/2026-11-03-simple-build-and-delegate.md` (§5.8), plus the HM1 changes to two existing reviewed owners, `launcher-instance.ts` and `storage-key.ts`. Source references are relative to `runner-v2/src/`. This is a static review of the change, not a sandbox; the regression coverage is `runner-v2/test/aiboard-home-store.test.ts`. The entry in `runner-v2/test/filesystem-mutation-routing.test.ts` refers to this record.

`aiboard-home-paths.ts` (new) computes paths and builds the fixed broker deny. It imports no `node:fs` API, so it needs no routing entry. The deny class it uses, `FixedPathDeny` in `remote-path-guard.ts`, uses only `lstat`/`realpath`/`stat` from `node:fs/promises`.

## Changes to reviewed owners

- `launcher-instance.ts` (class 3 in the 2026-10-31 review): `tryAcquireLock` now delegates to the new exported `tryAcquireLockFile(file)`, which has the same body: lock-file identity assertion, `DatabaseSync(sqliteDatabaseLocation(file), { timeout: 0 })` and `BEGIN IMMEDIATE`. `acquireLockFile(file, waitMs)` polls it every 50 ms and returns null when the wait runs out. `userDataRoot` is now exported. No new mutation-capable import and no new target kind: the home lock is a fixed name under `<home>`, created 0600 with its `.identity` record, exactly like the launcher locks. The store queues its own writers per lock path (`withHomeLock`) before any of them calls `acquireLockFile`. On POSIX, closing any descriptor of a file releases every fcntl lock the process holds on it, and the lock-file identity check opens and closes the file on each poll. So a second writer in the same process must never probe the file while the first one holds it, or a writer in another process could enter at the same time. The launcher's own discovery and lifetime locks are unchanged.
- `storage-key.ts` (class 3): `FileStorageKeyProvider` takes an optional file name, either `"storage-key"` (the default, unchanged) or `"home-key"`. Creation is still an exclusive random temporary plus a hard link, and the provider unlinks only the temporary it created. No new import.
- `self-update.ts` (class 3): `userStatePaths` also lists the home's files by name (`config.json`, `credentials.json`, `home-lock.sqlite` with its identity record and journal, and `home-key`), so `aiboard uninstall --remove-state` deletes settings and keys and leaves the rest of `~/.aiboard` or `AIBOARD_HOME` alone. The uninstall prompt now names them. This uses the existing `rm` path; there is no new import.

## Broker deny (not a filesystem owner, recorded for completeness)

`tool-broker.ts` now applies `FixedPathDeny` to every tool's declared paths, for every actor and before the remote/local_mcp guard. The deny covers `credentials.json*`, `home-lock.sqlite*` and `<data root>/home-key*` in every mode, and `config.json*` for write and delete. It also refuses delete and `fs.search` on a folder that holds one of those files. Resolution follows the guard's method: the lexical spelling, the canonical path through symlinks and junctions (the nearest existing parent for a missing leaf), and object identity of the target and of each denied file's parent folders. On Windows, alternate-data-stream suffixes and trailing dots or spaces are stripped first. Commands at an unconfined level can still read the files, as the plan's custody note says.
