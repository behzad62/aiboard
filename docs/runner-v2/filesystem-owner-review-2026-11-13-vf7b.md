# Runner V2 filesystem owner review — 2026-11-13, VF7b (Playwright CLI sessions)

Scope: the new native filesystem owner `runner-v2/src/playwright-cli.ts`, added by packet VF7b of `docs/plans/2026-11-13-build-verification.md` (§4.5), with the design of `docs/runner-v2/playwright-cli-spike-2026-11-13.md` §9. Source references are relative to `runner-v2/src/`. This is a static review of the change, not a sandbox; the regression coverage is `runner-v2/test/playwright-cli-session.test.ts`. The entry in `runner-v2/test/filesystem-mutation-routing.test.ts` refers to this record.

The other new modules import no mutation-capable `node:fs` API: `browser-install.ts` (`existsSync` only; the Chromium download is Playwright's own code, run by the owner's `aiboard browser install`), and `playwright-cli-guard.mjs` (`realpathSync` only). `portable-process-posix-control.mjs` gains a read-only `readdirSync`/`readFileSync` of `/proc` for `listPosixProcessCommands`.

| Module | Mutation-capable imports | Classification | Targets and derivation | Evidence | Concerns |
| --- | --- | --- | --- | --- | --- |
| playwright-cli.ts | chmodSync, mkdirSync, renameSync, rmSync, writeFileSync | 2: Runner-private state | `<state>/pw/bin/` and its four fixed shim names (`playwright-cli`, `playwright-cli-session`, each with `.cmd` on Windows), written by `installPlaywrightCliShims` at Runner start; the owner state folders `<state>/pw/r-<12 hex of runId>/t-<8 hex of runId+sessionId>/`, removed by `removeOwnerFolder` (POSIX, after the session's daemon stopped and no live process names the folder), `removeRun` (the run's folder, after its ExecutionHost binding closed and every owned process stopped) and `reconcileStartup` (`r-<12 hex>` folders no live process names); on POSIX the fallback socket folder `<tmp>/aib-<8 hex>`, removed with its owner folder. `<state>` is the Runner's configured state directory (`runner-start.ts`), which startup already refuses inside the project. No name is model-selected: every path is derived from Runner ids by fixed hashes. | Shims: `mkdirSync(recursive)`, an exclusive per-process temporary `<target>.<pid>.tmp` then `renameSync` over the target, only when the content differs, and `chmodSync(0o755)` on POSIX. Removals: `rmSync(recursive, force)` of exactly the derived folder; `reconcileStartup` filters the run folders with `/^r-[0-9a-f]{12}$/` first. The folders themselves are created by the session command (`mkdir`/`mkdir -p` in the shim), inside the Runner's state, and by Playwright's daemon (registry, socket, Chrome's temp profile under the owner's `tmp`). | (a) The shim folder is put first on PATH for the processes the Runner starts for an opted-in run; a process of the same user could replace a shim between writes, as with any per-user state. (b) `.aiboard-browser/` in the agent's workspace is created by the session command, not by this module: it is the daemon's output folder, with a `.gitignore` of `*` so git never sees it. (c) On Windows a folder a live Chrome still holds can resist `rmSync`; the run's folder is then removed at the next `removeRun` or `reconcileStartup`. |
