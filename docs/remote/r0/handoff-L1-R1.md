## L1 — local CLI

Scope:

- Provide `aiboard` runner selection, current-directory project, instance reuse, `status`, `stop`, `version`, `doctor`, `--help` and `--no-open` (`docs/plans/2026-10-27-aiboard-remote.md:159`).

- Open one connect tab with an instance-bound, single-use code and loopback port list; exchange it for separate per-runner session credentials (`docs/remote/r0/adr/ADR-F-browser-connect-handoff.md:13`).

- Add local stdio MCP through the Runner authority; publish only the available subset of the shared surface until its dependencies are implemented (`docs/remote/r0/remote-tool-surface.md:19`).

Out of scope: L2 installers, signing and release bundles; S1 whole-machine path enforcement; R2 durable job APIs; relay/cloud identity, billing, GUI plugins and Build-level remote tools. Do not reintroduce the legacy runner into product Build mode (`AGENTS.md:36`, `AGENTS.md:54`).

## R1 — Runner-bound connector

Scope:

- Compose an outbound WSS connector inside Runner ownership; dispatch exclusively via a dedicated external principal, `ExecutionHost` binding, `ToolBroker` and enabled Extension Management tools (`docs/remote/r0/adr/ADR-A-connector-in-runner-lifecycle.md:17`, `runner-v2/src/execution-host.ts:145`).
- Verify device proof, principal, audience/scope/expiry/nonce and epoch locally before admission; keep Runner-issued grants, role restrictions, exact process ownership and locally chosen policy (`docs/remote/r0/adr/ADR-A-connector-in-runner-lifecycle.md:19`).
- Reconcile before tool-ready, advertise per-tool degradation, supervise plugin failures, and shut down transport and owned resources in order (`docs/remote/r0/adr/ADR-A-connector-in-runner-lifecycle.md:31`).
- Build a narrow, durable record-before-dispatch foundation compatible with R2; keep effectful operations disabled until their full R2 recovery/idempotency rules and S1 policy are implemented (`docs/remote/r0/adr/ADR-C-remote-jobs-idempotency-cancellation.md:13`).
- Provide remote terminal start/status/logout and a fake-relay acceptance path; real account pairing/claim issuance depends on P1 (`docs/plans/2026-10-27-aiboard-remote.md:180`, `docs/plans/2026-10-27-aiboard-remote.md:215`).
- Honor D17 after S1: process/shell on, no per-action approval and audit on by default; the device owner can enable per-command approval or select read-only, cwd-only or shell off. Only the local user may broaden policy; enabled approvals use the terminal or a signed, job-bound dashboard decision (`docs/plans/2026-10-27-aiboard-remote.md:187`). Show the one-time notice and do not claim file exclusions confine default commands (`docs/plans/2026-10-27-aiboard-remote.md:186`, `docs/plans/2026-10-27-aiboard-remote.md:188`).

Out of scope: S1 whole-machine denylist and opt-in command controls; full R2 scheduling/cancellation/result retention; R3 chunking; R4 relay hardening; P1/P2 identity and public MCP gateway; X1 GUI catalog and X3 Build tools. Until S1, tests use isolated, non-secret fixture paths and owned test processes: do not advertise arbitrary production file/process access. Do not expose `git_commit` or hash-based artifact/image reads until their separate authorization designs are complete (`docs/remote/r0/remote-tool-surface.md:59`).

### Minimal fake-relay scenario

Use `runner-v2/test/remote-fake-relay.test.ts` and the three new fixtures above. The test hosts an **in-process WSS server** with a synthetic test certificate and real TLS/WebSocket handshake over paired in-memory duplex streams; for the child Runner, carry that duplex over an inherited anonymous pipe. Bind no TCP/UDP port, make no DNS or external calls, and inject a test-only signing authority/clock through the same verifier interface used by the connector. The child uses the same Runner composition and SIGINT handler as the CLI; never add a production flag that disables authentication.

1. Generate synthetic Ed25519 device credentials; authenticate the challenge and verified account/client/device/scope claims. Assert `authenticating` → `connected-degraded` → `tool-ready` only after recovery. Reuse `contracts/fixtures/valid/connection-state.valid.authenticating.json`, `connection-state.valid.degraded.json` and `connection-state.valid.ready.json` as shape examples (`docs/remote/r0/contracts/README.md:11`).
2. Send `contracts/fixtures/valid/remote-request.valid.read.json` at its fixed clock/epoch and read an isolated `README.md` through the actual `files_read` → `fs.read` → `ToolBroker` path; assert a Runner-issued grant, one dispatch and an admitted job response. Reuse the admitted response fixture for its union shape, not its write-specific IDs/status (`docs/remote/r0/contracts/fixtures/valid/remote-request.valid.read.json:2`, `docs/remote/r0/contracts/fixtures/valid/remote-response.valid.admitted.json:2`).
3. Resign a request with a mismatched authorized scope; assert a typed denial, no job admission and **zero additional broker/tool invocations**. Also use `contracts/fixtures/invalid/remote-request.invalid.device-epoch-mismatch.json` with highest epoch `5` (`docs/remote/r0/contracts/README.md:37`).
4. Under the same exact remote owner, create a benign managed process in the harness and read its output through the broker; install and locally approve the synthetic read-only MCP fixture, then call its allowed tool (`runner-v2/test/extension-mcp.test.ts:125`, `runner-v2/src/managed-process.ts:186`).
5. Trigger the new crash-once fixture after it is ready. Assert `connected-degraded` with `optional_tool_unavailable` or `required_tool_unavailable`, the failed tool unavailable, and no replay of the interrupted call; restart/re-attest the same executable and schema, then assert `tool-ready` and a fresh successful call. The allowed reason codes are in `docs/remote/r0/contracts/connection-state.v1.schema.json:141`.
6. Send real SIGINT to the Runner child. Await its exit and verify, using owned process handles and recorded identity, that the managed process, MCP child and Runner descendants have stopped; assert transport/timers and admission close first. Cleanup failure must remain a typed blocker, never a false success (`runner-v2/src/runner-resource-cleanup.ts:118`).
