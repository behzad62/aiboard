# L2 release review — 2026-10-30

Release `0.2.0` is **not approved for signing**. The independent review covered PR #109 at `ef529ff62a91d15f6b8125d4ade63ff6ba04b5af`; no security acceptance was issued. Work after that revision is provisional until independently reviewed and tested.

## Installer and release findings

1. **Install/update lock ownership:** installers and updater could remove an ownerless, stale-looking, or replaced lock. Windows uninstall also released the lock before publishing and executing its deferred cleanup, which can race a subsequent install and delete its files or state. The acquisition changes in `5912525d` do not close the deferred Windows cleanup race; ownership must cover the destructive handoff and cleanup.
2. **Same-version repair:** the reviewed installers could report success without verifying a damaged installed version. The first repair at `5912525d` still executed the retained verifier before authenticating it. Follow-up `5c1bc493` stages a signed-checksum-verified bundle and uses its verifier to compare the installed inventory; the follow-up requires independent review and hosted platform evidence.
3. **Sequence monotonicity:** explicit release sequences could repeat or regress. `e1d3c1f1` compares against authenticated history; `285ce35a` adds a separate previous-channel history witness for key rotation or changed origins/floors. Independent follow-up found that this only compares against the dispatched checkout: two serialized drafts cut before the manifest commit can still receive the same sequence. A durable reservation across signing runs is required. A compromised signer can also issue the maximum allowed sequence, so key-compromise recovery cannot always choose a higher sequence; it needs an independently reviewed reinstall/reset or epoch procedure. Rotation needs CLI-level and removed-key trust tests.
4. **Copilot bundle:** the account peer runner imports a Copilot helper that the reviewed bundle omitted. A provisional builder change includes the helper, SDK and lockfile-authenticated target package. Independent review checked all six real pinned platform archives; local Windows and Linux bundles started the SDK, answered a local ping, and closed its direct child. Cross-host build parity and all six hosted target smokes remain pending. The general dependency closure is copied from `node_modules` after version checks; production provenance relies on fresh `npm ci` and independent cross-host builds. The smoke controller cannot establish cleanup of an uncooperative child or arbitrary detached descendants; exact process containment and bounded settlement remain open.
5. **Bounded processes:** the shell and PowerShell installers do not bound the staged inventory and smoke processes. A hang must not release a lock or clean up files while the child may still run.
6. **Redirect transport:** the shell wget fallback and updater's automatic redirects can follow HTTPS to HTTP; integrity is still protected by signatures and hashes, but the documented HTTPS-only transport is not established. Audit PowerShell redirects too.
7. **Retained local inventory:** the updater checks a mutable installed inventory against mutable files; a local writer able to change both is outside what that check authenticates. Do not claim that check alone defeats a local attacker.

## CI and filesystem investigation

- The [installer matrix](https://github.com/behzad62/aiboard/actions/runs/41086963238) passed at `ef529ff6`; it does not validate later fixes.
- The [portable workflow](https://github.com/behzad62/aiboard/actions/runs/41086963232) exposed an unchanged `main` ownership-audit failure and a Linux missing-path assertion. A focused reproduction on main confirmed the ownership-audit failure. A later independent AST scan found 26 distinct modules outside the audit's reviewed sets: 21 provisionally grouped as private-state/extension/launcher/remote owners, one project-worktree owner, two release owners, and two read-handle-only candidates. These are descriptions, not approvals; they have not been cleared and must not be blanket-allowlisted. The count is limited to the static import rule, not all possible mutation channels.
- The Linux missing-path assertion predates the `fs.stat` contract that returns `{ exists: false }`. `d545a2da` retains hidden-alias and hidden-content checks and updates only that missing-path control. The focused case passed on Windows and in a Linux Node 24 container; macOS and integrated evidence remain pending.
- Independent CI review confirmed the Windows T8 job hit its 30-minute limit. Before interruption the native patch factory journey reported `delivery_boundary_unavailable` and subprocess cleanup unverified in `backend_unavailable`; its fixture root was retained. The log does not establish why cleanup was unavailable. This is a Windows ownership/settlement investigation, not a reason to raise the timeout or bypass coverage.
- [Windows factory diagnostic 41104377370](https://github.com/behzad62/aiboard/actions/runs/41104377370) runs the single pre-existing observer-enabled diagnostic against `ef529ff62a91d15f6b8125d4ade63ff6ba04b5af`, the same tree as the failing PR merge checkout. A pass is not an integrated qualification or proof of the original failure's cause; passive failure captures are not proof of ownership or release.
- The installer end-to-end test at `2b98fb6a` passed 72 checks on Linux in an isolated Node 24 container, including jointly modified file/inventory and non-executable retained Node cases. This predates the provisional Copilot packaging change and does not replace hosted Windows/macOS installer evidence.
- The reviewer identified possible external report deletion through a symlinked workspace parent in `delivery-execution.ts` cleanup, and a stale-lock replacement race in `extension-registry.ts`. Both require bounded reproductions and ownership-safe fixes; neither is cleared.
- The [benchmark workflow](https://github.com/behzad62/aiboard/actions/runs/41086963198) failed a cancellation test on unchanged main because its fake runner lacked the browser capability required by the current ToolBench suite. `f5769ef6` and `65e93ee4` update that fixture and add a browser-unavailable negative control; targeted local tests passed, hosted evidence remains pending.

No draft release or signed production manifest has been created. Do not merge or publish while these findings are unresolved. The live site remains at its previously deployed revision, with installers failing closed because no signed manifest exists.
