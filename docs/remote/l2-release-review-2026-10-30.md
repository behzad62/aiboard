# L2 release review — 2026-10-30

Release `0.2.0` is **not approved for signing**. The independent review covered PR #109 at `ef529ff62a91d15f6b8125d4ade63ff6ba04b5af`; no security acceptance was issued. Work after that revision is provisional until independently reviewed and tested.

## Installer and release findings

1. **Install/update lock ownership:** installers and updater could remove an ownerless, stale-looking, or replaced lock. Windows uninstall also released the lock before publishing and executing its deferred cleanup, which can race a subsequent install and delete its files or state. The acquisition changes in `5912525d` do not close the deferred Windows cleanup race; ownership must cover the destructive handoff and cleanup. The legacy batch helper also serializes Unicode paths through Latin-1 after CMD quoting, which can alter command syntax; use literal, Unicode-safe APIs. The Windows remove-state path omits the default extensions directory, so it cannot claim all state was deleted.
2. **Same-version repair:** the reviewed installers could report success without verifying a damaged installed version. The first repair at `5912525d` still executed the retained verifier before authenticating it. Follow-up `5c1bc493` stages a signed-checksum-verified bundle and uses its verifier to compare the installed inventory; the follow-up requires independent review and hosted platform evidence.
3. **Sequence monotonicity:** explicit release sequences could repeat or regress. `e1d3c1f1` compares against authenticated history; `285ce35a` adds a separate previous-channel history witness for key rotation or changed origins/floors. Independent follow-up found that this only compares against the dispatched checkout: two serialized drafts cut before the manifest commit can still receive the same sequence. A durable reservation across signing runs is required, but unique reservations alone do not prevent publishing drafts out of order. A queued old checkout can also carry obsolete key policy. The design needs a serialized signing authority, protected durable history, and current-policy/monotonic publication checks; preserve the existing expired-manifest semantics. A compromised signer can issue the maximum sequence, so recovery cannot always choose a higher sequence; it needs an independently reviewed reinstall/reset or epoch procedure. Rotation needs CLI-level and removed-key trust tests.
4. **Copilot bundle:** the account peer runner imports a Copilot helper that the reviewed bundle omitted. A provisional builder change includes the helper, SDK and lockfile-authenticated target package. Independent review checked all six real pinned platform archives; local Windows and Linux bundles started the SDK, answered a local ping, and closed its direct child. Full six-target cross-host build parity and all six hosted target smokes remain pending. The general dependency closure is copied from `node_modules` after version checks; production provenance relies on fresh `npm ci` and independent cross-host builds. The smoke controller cannot establish cleanup of an uncooperative child or arbitrary detached descendants; exact process containment and bounded settlement remain open.
5. **Bounded processes:** the shell and PowerShell installers do not bound the staged inventory and smoke processes. A hang must not release a lock or clean up files while the child may still run.
6. **Redirect transport:** the shell wget fallback and the reviewed updater's automatic redirects can follow HTTPS to HTTP; integrity is still protected by signatures and hashes, but the documented HTTPS-only transport is not established across all installers. A locally tested updater change manually follows at most five redirects and refuses an HTTPS-to-HTTP transition before contacting it; independent review accepted that HTTPS-only scope. It does not claim an SSRF/no-loopback-destination policy. The shell fallback and PowerShell still need their own fixes and tests.
7. **Retained local inventory:** the updater checks a mutable installed inventory against mutable files; a local writer able to change both is outside what that check authenticates. Do not claim that check alone defeats a local attacker.

### Windows T8 timeout (run 41086963232, job 124170520246)

- At 583 s the native patch factory journey paused with `delivery_boundary_unavailable` and detail "Process observation or termination failed.". That text is the generic wrapper at `subprocess-runtime.ts:895-900`. The underlying error is attached only as `cause` on the thrown error; it is not in the pause detail or the log, so the log cannot identify which backend operation failed.
- Teardown then failed: `NativeBuildResourceCleanupStack.close` reported that native Build handle resources could not all be closed, and the ExecutionHost run-binding cleanup also failed. The owned root was retained. The test process then stayed alive for about 19 more minutes until the 30-minute job limit cancelled it; node:test reported "Promise resolution is still pending". This second failure is itself an unbounded-settlement defect: a failed cleanup left something holding the event loop.
- Local Windows reproduction attempts on this branch: the factory test file alone passed in 250 s. The same tree in isolation also passed in CI ([diagnostic 41104377370](https://github.com/behzad62/aiboard/actions/runs/41104377370), 533 s). The exact 9-file Windows T8 command, run locally on this branch (Windows 10, Node 24.18.0), finished in 263 s with 127/128 passing. The factory journey passed with no hang; the only failure was the pre-existing owner audit. The CI failure therefore did not reproduce, and its root cause is not established.
- Recommended next step, under the Task 12 bounded-gate process: preserve the `cause` chain in the subprocess runtime's `backend_unavailable` failure and pause detail (diagnostic only, no semantic change). Bound the factory test teardown so a failed resource close fails fast instead of holding the job. Then rerun the integrated Windows T8 step. Neither change was made here: both are Runner V2 lifecycle code, governed by `docs/runner-v2/task-12-bounded-gates.md`. Do not raise the 30-minute limit.
